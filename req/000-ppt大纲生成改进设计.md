# PPT 大纲生成改进设计

参考：`000-PPT生成的三层提示词模板.docx`、现有 `ppt生成设计.md` / `ppt版面定位设计.md`，以及当前「Markdown 大纲 → 逐页填模板」链路。

目标有两块：

1. **成稿质量**：ppt的生成，不仅仅是行业报告、也不一定是决策稿，也不是复述素材目录，而是根据用户给定的主题，生成一个通用的PPT幻灯片。
2. **大纲交互**：对话过程中的markdown文本不再编辑（去掉大纲修改，仅保留大纲保存），在大纲管理页面中，用户改可见字段，槽信息与元信息由系统维护。

---

## 1. 三层提示词怎么接到毕方

模板里的三层对上现有链路如下。不要把「选品五桶 + 7:2:1」写死进知识库写作；那是领域框架，换主题类型才换。

| 模板层 | 毕方落点 | 谁改 |
|---|---|---|
| **不变骨架** | 系统提示词：角色、输出契约（页字段 / 出处）、叙事转换、禁止编造、证据与推演分开 | 产品内置，用户不改 |
| **领域框架** | 可选「主题类型」包：选品 / 汇报 / 复盘……对应决策链、桶、阈值 | 管理员或高级配置；普通用户只选包 |
| **变量层** | 大纲构思表单：岗位、对象、范围、素材形态、页数、口径 | 每次生成前填写 |

**分层写入约定（勿串层）**

| 层 | 写什么 | 不写什么 | 注入时机 |
|---|---|---|---|
| 骨架·结构 | 标题树密度、页语义分工、同页对照偏好 | layout / tips 语法、领域决策链 | 结构段 system |
| 骨架·选型 | layout 枚举与选型 | tips 写法、领域全文 | 章选型 system |
| 骨架·填充 | 锁定/兄弟页分工、本页 tips 语法 | 改标题树、领域阈值 | 按页填充 system |
| 领域 | 决策顺序、章主题参考、领域禁忌 | layout / tips 语法、条数硬规则 | 结构段 + 按页填充（选型不加） |
| 变量 | 主题、岗位、对象、范围 + 一句决策视角 | 层级/版式/领域全文 | 用户气泡 |

**用户可见度**

| 内容 | 定框弹窗 | 对话气泡 | API system |
|---|---|---|---|
| 骨架 / 领域全文 | 不展示 | 不展示 | 按上表注入 |
| 主题类型 | 「高级」折叠 | 不展示 | — |
| 岗位 / 对象 / 范围 / 显示名 | 可改 | 拼进短句 | — |
| 用户短句 | 可预览 | 唯一可见提示 | 作 user |

**生成链路（已定）**

1. **三段流水线**：结构(+领域) → 章内选型(仅 layout 目录) → 按页填充(CORE+本页细则+领域禁忌) → Markdown。  
2. 对话气泡仍只见变量短句；骨架与领域全文不进气泡。

六步流程与现状的对应：

| 步骤 | 模板动作 | 毕方现状 | 改进 |
|---|---|---|---|
| 1 素材入库 | 可检索文本 | 知识库切片已有 | 保持 |
| 2 主题定框 | 填变量表 | 只有一个「主题」输入框 | 拆成变量槽（岗位 / 对象 / 范围 / N） |
| 3 筛选打标 | 按桶打标 | 无 | 大纲页可带可选 `bucket`，知识库稿可不强求 |
| 4 大纲结构 | 素材线 → 决策线 | 模型自由写 `#/##/###` | 强制按决策链分章；每页带 layout / 出处 |
| 5 逐页要点 | 摘证据、下判断 | 已有 slide 生成 | 区分 `evidence` / `inference`；数据卡短解读不复述标题 |
| 6 渲染质检 | 排版与数字核对 | 下载填模板 | 版式控件 + 页级失败提示 |

**推演页（如行动清单）**：允许，但必须标 `kind: inference`，且不得出现检索里没有的数字和周期。知识库 PPT 默认仍以证据页为主。

## 2. 为什么 Markdown 直改不够

现在大纲存的是一整段 `outlineContent` 字符串。`layout: metric`、将来的章节副标题、出处页码、推演标记都只能塞进 Markdown 行里。用户一改就容易：

- 删掉或改乱版式行；
- 把系统元信息当成正文要点；
- 无法单独调某一页的版式，而不动要点文字。

内容生成侧已经用结构化小项 + 抽屉编辑，大纲侧应对齐同一思路。

## 3. 大纲数据模型（结构化）

存储从「纯 Markdown」改为 **结构化 JSON**，Markdown 仅作导入 / 导出 / 给模型的过渡格式。

```ts
type OutlineDoc = {
  id: string;
  title: string;                 // 全文标题，用户可见
  meta: {
    kbName?: string;
    domainPack?: 'selection' | 'report' | 'review' | 'generic';
    variables: {                 // 变量层，用户可见
      role: string;              // 岗位
      object: string;            // 对象
      scope: string;             // 范围
      materialForm?: string;
      pageTarget?: string;       // 如 12～15
      actionQuestion?: string;   // 读完要做什么
    };
  };
  chapters: OutlineChapter[];
};

type OutlineChapter = {
  id: string;
  title: string;                 // 用户可见
  subtitle?: string;             // 目录一句说明，用户可选改
  slides: OutlineSlide[];
};

type OutlineSlide = {
  id: string;
  title: string;                 // 用户可见
  subtitle?: string;             // 一页一句结论，用户可见
  layout: 'list' | 'metric' | 'columns' | 'metric_columns' | 'metric_list';  // 系统默认，用户可用下拉改
  kind: 'evidence' | 'inference'; // 系统默认；推演页打标
  tips: OutlineTip[];            // 3～5（list）或 2～4（metric）
};

type OutlineTip = {
  text: string;                  // 用户可见
  sourceRef?: string;            // 出处，系统优先填，用户可改
  bucket?: string;               // 领域桶，可选，默认隐藏
};
```

兼容策略：

- 读旧记录：仍用现有 `getChaptersFromContent` 解析 Markdown，再填入默认 `layout/kind`。
- 写新记录：存 JSON；导出 `.md` 时再渲染成 `#/##/###/-`。
- 给模型的提示词：由结构化字段拼装，用户看不到完整系统约束。

## 4. 大纲编辑 UI：暴露什么、藏什么

交互对齐「内容生成」：左侧章节树 + 右侧页编辑，**不用大段 Markdown 当主编辑器**。

### 用户可改（控件）

| 层级 | 控件 | 说明 |
|---|---|---|
| 文章 | 标题输入 | 全文标题 |
| 文章 | 变量表单 | 岗位 / 对象 / 范围 / 页数目标（构思时填，保存后只读或可再编辑） |
| 章节 | 标题、可选副标题 | 对应目录说明 |
| 章节 | 增删 / 上移下移 | 按钮 |
| 页 | 标题、可选副标题 | 输入框 |
| 页 | 版式下拉 | `列表` / `数据卡` /（后续）`多列` |
| 页 | 要点列表 | 与内容抽屉类似：增删改、条数校验 |
| 页 | 重新生成本页大纲要点 | 按钮，只重写 tips |

### 系统维护（默认不暴露）

| 字段 | 谁写 | 是否给用户看 |
|---|---|---|
| `layout` 自动推断 | 要点含 ≥2 个原数字 → metric | 下拉可改，不在 Markdown 里露出 |
| `kind: inference` | 标题含「行动清单 / 归纳」或领域包规则 | 仅标签，不可自由输入阈值 |
| `sourceRef` | 大纲生成时从检索编号带出 | 高级折叠区可看 |
| `bucket` | 领域包打标 | 默认隐藏 |
| 章节页是否插入 | 下载时按章插入 `chapterCover` | 不进大纲编辑 |
| 封面 / 目录 / 尾页字段 | 下载时规则填 | 大纲里不编辑 |

预览抽屉右侧：默认用**结构化树**展示（章 → 页 → 要点），不再主推 Markdown 原文。需要排查时再提供「高级：查看原始 Markdown / JSON」。

## 5. 生成质量规则（接到提示词）

### 5.1 全局（定大纲）

- 不要沿用素材原有章节顺序；按变量层「决策链」分章。
- 每页标题 ≤20 字；页下只有规定条数的要点；可有一句副标题结论。
- 只保留与「范围」相关的内容。
- 证据页：每条能指回检索；推演页：显式 `kind: inference`，且不发明数字。
- 版式：数字页用 metric；对照 / 赛道 / 打法后续用 columns；其余 list。

### 5.2 单页（定要点 / 定正文）

- 摘取证据：只用原文数字、术语。
- 解读不重复章节名与本页标题（数据卡 4～16 字已落地，列表页同样适用）。
- 推演判断必须标注；知识库 PPT 默认不做「各 20 分 / 7:2:1」这类阈值，除非领域包显式开启且页面标为推演。

### 5.3 与 WorkBuddy 对标的边界

学：决策顺序、版式变化、短要点、目录带说明、章节页。  
不学进证据页：报告里没有的比例、天数、周任务常数。

### 5.4 `columns` 占位符约定（已定）

对标 WorkBuddy 分栏页（赛道 / 五维 / 打法）：**栏有标题（可有一句副标），栏内是短词/短句，不强制 list 式长 Desc。**  
填充引擎只支持一层嵌套（`{a.b}`），与现有 `PptTemplate.genNewContentByTpl` 一致。

**页级**

| 占位符 | 必填 | 说明 |
|---|---|---|
| `{slideTitle}` | 是 | 本页标题 |

**栏级（`N` = 1…栏数；模板第 28–31 页 = 2～5 栏，每栏预留 item1…item5）**

| 占位符 | 必填 | 说明 |
|---|---|---|
| `{colNTitle}` | 是 | 栏标题，宜 ≤12 字 |
| `{colNSub}` | 否 | 栏副标/口诀，一句，宜 ≤20 字；模板可留空槽 |

**栏内条目（`M` = 1…该栏条数，建议每栏 2～5 条）**

| 占位符 | 必填 | 说明 |
|---|---|---|
| `{colN.itemM}` | 是 | 短词或短句，宜 4～16 字 |
| `{colN.itemM_Desc}` | **否** | 默认不填、模板可不放；需要补充说明时才用，宜 ≤28 字 |

**模板排版示例（3 栏 × 每栏最多 5 条）**

```text
{slideTitle}

{col1Title}          {col2Title}          {col3Title}
{col1Sub}            {col2Sub}            {col3Sub}
{col1.item1}         {col2.item1}         {col3.item1}
{col1.item2}         {col2.item2}         {col3.item2}
{col1.item3}         {col2.item3}         {col3.item3}
{col1.item4}         {col2.item4}         {col3.item4}
{col1.item5}         {col2.item5}         {col3.item5}
```

**灌数对象形状（代码侧）**

```ts
{
  slideTitle: string;
  col1Title: string; col1Sub?: string;
  col1: { item1: string; item2?: string; /* … */ item5?: string };
  col2Title: string; col2Sub?: string;
  col2: { item1: string; /* … */ };
  // col3 …
}
```

**明确不做**

- 不用 `{vItem.itemN}` / `{vItem.itemN_Desc}` 充当 columns（那是 list/metric 的槽）。
- 栏内条目**不**按 list 的「标题 4～12 + 描述 20～70」校验。
- 「六大风格」那种「名 + 增速 + 品类/颜色 + 一句解读」另定卡片/metric_columns，不塞进本约定。

**大纲 Markdown（接入时）**：`- layout: columns`，其下按栏写：

```text
- col: 热点赛道
- colSub: 保基本盘
- 休闲裤
- T恤
- col: 机会赛道
- 短裤
- 羽绒服
```

生成/校验按上表，`colSub` 与 item Desc 非必须。禁止无 `col:` 的伪分栏长句。

### 5.5 `metric` 与 `metric_columns` 占位符约定（已定）

#### A. `metric`（纯数据卡，已落地；模板第 24–27 页 = 2～5 卡）

对标模板第 24～27 页。槽位与 list 同形，但语义不同：`item` = **原数字**，`item_Desc` = **短口径**（不是 list 长描述）。

| 占位符 | 必填 | 说明 |
|---|---|---|
| `{slideTitle}` | 是 | 本页标题 |
| `{vItem.itemN}` | 是 | 原数字，2～12 字，须含 `%` / `亿` / `万` 等 |
| `{vItem.itemN_Desc}` | 是 | 短口径，4～16 字，只说明数字指什么 |

`N` = 1…2 / 3 / 4 / 5（对应页 24 / 25 / 26 / 27）。不要用 `col*`。

```text
{slideTitle}
{vItem.item1}     {vItem.item2}     {vItem.item3}
{vItem.item1_Desc}{vItem.item2_Desc}{vItem.item3_Desc}
```

灌数：现有 `SlideVar.vItem` + `padMetricVItem`（槽位 2～5）。

#### B. `metric_columns`（上数据卡 + 下分栏；模板第 32–36 页）

一页同时有 **KPI 横排** 和 **下方分栏短要点**。

| 模板页 | 上半卡数 | 下半栏数 |
|---|---|---|
| 32～35 | 2～5 | 2 |
| 36 | 5 | 3 |

**上半：数据卡（与 metric 同槽）** — `{vItem.item*}` / `{vItem.item*_Desc}`  
**下半：分栏（与 §5.4 同槽）** — `{colNTitle}` `{colNSub}` `{colN.itemM}`（Desc 非必须）

```text
{slideTitle}

{vItem.item1}   {vItem.item2}   …
{vItem.item1_Desc} …

{col1Title}                      {col2Title}
{col1Sub}                        {col2Sub}
{col1.item1}                     {col2.item1}
…
```

**灌数对象形状**

```ts
{
  slideTitle: string;
  vItem: {
    item1: string; item1_Desc: string;
    item2: string; item2_Desc: string;
    // … itemK
  };
  col1Title: string; col1Sub?: string;
  col1: { item1: string; item2?: string; item3?: string; item4?: string };
  col2Title: string; col2Sub?: string;
  col2: { item1: string; /* … */ };
}
```

**大纲（接入时）**：`- layout: metric_columns`；要点用前缀区分，例如 `- metric: 38% 线上渠道占比` 与栏内 `- list:` / 或按栏分组写法（实现时再定序列化细节）。校验：上半按 metric，下半按 columns（短条目、Desc 非必须）。

#### C. `metric_list`（上数据卡 + 下清单；模板第 37–41 页，已落地）

适用：同页既要 **原数字卡** 又要 **判断/机会清单**，且下半**不必分栏**（例：「586 亿 / +42.3%」+「核心类目多数超大盘」）。  
有并列分维（热点 / 机会 / 新赛道）时仍优先 `metric_columns`。

**与 `metric_columns` 的差别**：下半是纵向 list（`vItem2`），不是 `colN*`。

| 模板页 | 上半卡数 | 下半要点数 |
|---|---|---|
| 37～40 | 2～5 | 2 |
| 41 | 5 | 3 |

**页级**

| 占位符 | 必填 | 说明 |
|---|---|---|
| `{slideTitle}` | 是 | 本页标题 |

**上半：数据卡（与 metric 同槽）**

| 占位符 | 必填 | 说明 |
|---|---|---|
| `{vItem.itemN}` | 是 | 原数字，须含 `%` / `亿` / `万` 等 |
| `{vItem.itemN_Desc}` | 是 | 短口径，4～16 字 |

**下半：判断清单**

| 占位符 | 必填 | 说明 |
|---|---|---|
| `{vItem2.itemM}` | 是 | 短标题，4～12 字（或整句要点的前半） |
| `{vItem2.itemM_Desc}` | 否 | 短说明；可空 |

**灌数**：`buildMetricListFillVars` → 单页 `metric_list`（不再拆成 metric+list 两页）。选页：卡数 2～5 且要点 2 → 37～40；5 卡且要点 ≥3 → 41。

**大纲 Markdown**：`- layout: metric_list`，要点带前缀：

```text
- metric: 586亿 2024H1男装大盘销售额
- metric: +42.3% 同比增速
- list: 核心类目：多数增速超大盘
- list: 羽绒服/牛仔裤/马甲：显著高于大盘
```

**明确不做**：下半不要写成 `col:` 分栏；不要把「586亿…趋势」写成一整段 list。

#### D. 不算上述复合版式的

- **六大风格卡片**（名 + 增速 + 品类/颜色 + 一句解读）：另定 `metric_cards`，占位符大致为 `{cardNTitle}` `{cardNValue}` `{cardNTags}` `{cardNTakeaway}`，不塞进 `metric_columns` / `metric_list`。

## 7. 验收标准

- 用户改大纲时看不到 `- layout:` 原文，但能改「列表 / 数据卡」。
- 保存再打开后，版式与要点不丢。
- 知识库 PPT：证据页无编造数字；推演页有明确标记。
- 同题生成：章顺序贴近决策链，而不是报告目录复刻。
- 数据卡解读不复述本页标题。

## 8. 开放问题

1. 领域包（选品阈值）默认对知识库 PPT **关闭**还是「可选开启」？建议默认关闭，智能 PPT 可开。
2. 大纲存 localStorage 的 JSON 体积上限；是否很快迁服务端。
3. 出处页码：当前检索是 chunk 编号，是否映射成「文件名 + chunk」即可，还是要回原 PDF 页码（成本高）。

## 10. 源 PDF ↔ 生成 PPT 对照结论（衬衫/polo 样例，2026-09）

源：18 页图鉴型报告；生成：17 页。**框架成立，内容层暂不能对外。**  
页码级金标与复验清单见 [`生成PPT质量评审与技术改进指导.md`](./生成PPT质量评审与技术改进指导.md)。

### 10.1 效果三类问题

| 类 | 现象（页码级） | 根因落点 |
|---|---|---|
| **A 张冠李戴** | P5 衬衫 296.2万/3.3亿 被改写成「TOP 合计」；P9 竖条纹衬衫价安到 polo；P10 店铺销量交叉错配；P12 衬衫趋势拼 polo 店铺 | OCR 拍平表 + 同 chunk 多实体；检索跨品类；LLM 灌槽跨页拼贴 |
| **B 坏填充** | 残留 `progress1-5` 等内部标记；价格带「100-200元」截成 `100`/`200`；同文重复填两卡 | 模板占位未清；拆 run/截断；跨槽未去重 |
| **C 覆盖率低** | polo 核心 KPI 全丢；属性章/TOP10/爆款趋势缺失；除封面外零图零表 | 结构漏章；RAG 漏召；版式只走文字卡，无图鉴/表路由 |

### 10.2 技术改进优先级（采纳）

合并样例金标与 [`ppt设计评审-改进建议.md`](./ppt设计评审-改进建议.md)。**不换 template-filling 架构**；优先补闸门与模型缺口。

**P0（拦错 / 治本入库）**

1. **数值忠实性（大纲闸·填充闸）**：数字 ∈ 证据；数值+实体绑定（同 tip 口径 / 同 chunk 近邻）；禁止 TOP 合计改写品类大盘数。~~仅子串包含不够~~。
2. **表格原子 chunk + 元数据过滤**：指标名/数值/单位/品类/页码同原子；检索先过滤再向量。**随 P0-2 一并保存图片资产 + bbox + 页码**（避免 VL 重跑两次）。
3. **成品闸（缺）**：灌模后抽出全文——数值复核、`{slot}`/`progress` 残留、空槽、截断；页级失败提示。与大纲闸、填充闸组成三道闸。
4. **模板 manifest 化**：替代 `页码=风格×3+(项数-3)+起始` 硬编码；`template-manifest.json` 为 layout↔页↔slots 唯一真源。

**P1**

5. **结构化抽取库双轨 + 素材覆盖清单**：页级 JSON 直填；大纲前后对「必选表/榜/属性」做 coverage checklist（专治 C 类漏章）。
6. **OutlineDoc 复合版式槽位**：`columns` / `metric_*` 用 `slotGroup` 或 layout union，告别仅靠 `col:`/`metric:` 前缀；编辑 UI 分组。
7. **占位符单 run 规范 + 入库扫描**；`table` / `image_grid` 版式预留；metric_columns 组合降级规则写清。
8. **生成清理加固**：跨槽去重、标记过滤（灌模侧已有部分）。

**P2**

9. **版式路由 + eval 回归**：四指标自动化（金标见质量评审文档）；kind/layout 生成期输出；领域包冲突仲裁与 token 预算；文档页码表改引用 manifest。
