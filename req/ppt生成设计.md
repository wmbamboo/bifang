## ppt生成现状调研
**目前模式：大纲 → 逐页填空模板**

流程是：Markdown 大纲 → 按页 LLM 生成「标题-描述」小项 → 解析成结构化字段 → 往 `pptx` 模板占位符里灌（封面 / 目录 / list / 尾页）。这是典型的 **template-filling**，不是模型直接画版式。

**好不好？**  
合适：版式统一、可控、能挂 RAG、下载即用。
代价：强依赖解析格式、模板占位要齐、版式变化靠换模板而不是靠内容自适应；你们碰到的漏解析、字体变白、副标题不上页，都是这类架构的常见坑。

**常见别的生成模式**

| 模式 | 做法 | 优劣 |
|------|------|------|
| **A. 当前：结构化填模板** | 字段 → `{slideTitle}` / `{vItem.itemN}` | 可控、品牌一致；扩展靠模板 |
| **B. 代码画 PPT** | `pptxgenjs` 等按数据画形状 | 灵活、不依赖拆占位符；设计要自己写 |
| **C. 章节分隔页模式** | 每章先 `chapterCover`，再内容页 | 章节感更强；你们模板有 `chapterCover`，流程里还没用 |
| **D. 整稿一次生成** | 一次出全稿 JSON/Markdown 再渲染 | 少请求、风格更统一；长文易糊、难局部重生成 |
| **E. HTML/Markdown → PPT** | 先排版再转 | 预览方便；转 pptx 质量参差 |
| **F. 幻灯片级 Agent** | 按页选型（图文/对比/数据）再填 | 表现力强；复杂、成本高 |
| **G. 商业 API** | Gamma / Beautiful.ai / Office 等 | 观感好；贵、难深度接知识库 |

**建议**  
不必换掉 A；优先把 A 做稳（解析、样式、选模板、可选章节分隔页）。若要「更好看/更灵活」，下一步更自然的是 **A + C（加章节页）**，或逐步引入 **B（部分页用代码画）**，而不是整站换成端到端生成。

我这边是 Ask 模式，只能给方案建议；若要改生成流程，需切到 Agent 模式。

## ppt-Agent
**幻灯片级 Agent**可以理解成：不再「每页都套同一种 list 模板」，而是**每一页先由 Agent 决定「这页该用哪种版式」**，再按该版式需要的字段去生成/填充。

---

### 和你们现在的差别

| | 现在 | 幻灯片级 Agent |
|--|------|----------------|
| 选型 | 几乎固定：cover → catalog → list×N → tail | 每页在候选版式里选一个 |
| 内容 | 统一「3～5 个 标题-描述」 | 按版式 schema 生成不同结构 |
| 复杂度 | 低 | 多一轮决策 + 多套模板/渲染 |

---

### 具体怎么做（推荐流水线）

**1. 版式目录（Layout Catalog）**  
先定义有限几种（别一上来几十种），例如：

- `list`：要点列表（你们已有）
- `compare`：左右/多列对比
- `metric`：大数字 + 解读
- `image_text`：左图右文 / 上文下图
- `timeline`：步骤/阶段
- `quote` / `summary`：金句或小结

每种对应：模板页（或 pptxgen 画法）+ **JSON Schema**（要哪些字段）。

**2. 页级 Planner（选型 Agent）**  
输入：PPT 总标题、章节名、本页 `slideTitle`、大纲 `subTitle`、可选知识库摘要。  
输出例如：

```json
{
  "layout": "metric",
  "reason": "副标题含明确销售额与增速",
  "need_image": false
}
```

可用小模型 + 规则兜底（标题含「对比」→ compare；含「亿/%/增速」→ metric）。

**3. 页级 Writer（填内容 Agent）**  
按选中 layout 的 schema 生成，例如 metric：

```json
{
  "headline": "大盘显著增长",
  "metrics": [{"label": "销售额", "value": "586亿"}, {"label": "同比", "value": "+42.3%"}],
  "takeaway": "增长趋势明确，宜加大高增长赛道投入"
}
```

compare 则是 `left/right` 两组要点，不再硬套 `vItem.item1..5`。

**4. Renderer**  
- 短期：每种 layout 对应模板里若干页（像现在的 list 3/4/5 项），占位符对齐 schema。  
- 中期：`pptxgenjs` 按 schema 画，少受「占位符拆 run」折磨。

**5. 编排**  
封面/目录/尾页仍规则生成；中间内容页：`for each slide: plan → write → render`。失败则回退 `list`。

---

### 在毕方里怎么落地（最小可行）

1. 先只加 **2 种**：`list`（现有）+ `metric`（或 `compare`）。  
2. Planner 先做 **规则 + 轻量 LLM**，不要纯自由发挥。  
3. Writer 输出 **严格 JSON**（用 schema 校验），再填模板。  
4. 成本控制：选型用小模型/非流式；同章可批量选型；缓存「标题→layout」。  
5. UI：结果页显示「本页版式：数据卡」，允许用户改版式后只重生成该页。

---

### 成本与风险（务实）

- 每页多 1 次选型调用（或批量一次出全部 layout）。  
- 版式一多，模板和维护成本上去——**先少而精**。  
- 知识库页：选型可参考副标题是否含数、是否「对比/vs」。  
- 解析失败问题会变成「JSON 校验失败」——比自由文本正则更好控。

---

### 一句话

**不是换一个大模型直接出 PPT，而是：有限版式库 + 每页「选型 Agent」+ 按 schema「写作 Agent」+ 对应渲染。** 你们现有的大纲/RAG/逐页生成都能复用，主要是在「一律 list」前面加一层选型，并多准备几套填空结构。

若要在仓库里试点（例如只加 metric），需要切到 Agent 模式我才能改代码。
## 改进思考
**1）按章换风格**  
你的判断对：**多数情况下不行。** 同一套母版里「多套 list」若配色/留白不一致，按章切换会像换皮。更稳的是：

- **整份 PPT 锁定一种 list 视觉**（同一配色、同一卡片语言）  
- 「变化」交给 **layout 类型**（list / 图文 / 数据卡），而不是换皮肤  
- 多套 list 仅作 **用户选模板时的风格包**（整包换），不要运行时按章/按页混用  

---

**2）科技风指定「图文结构」怎么处理、大纲/内容里怎么加**

核心：**把「版式」变成大纲或页元数据的一等公民**，不要只靠事后猜。

### 推荐做法：大纲阶段就标 layout

大纲不止 `### 标题` + `- 要点`，加一行版式约定，例如：

```markdown
### 架构总览
- layout: image_text
- image: architecture|diagram|placeholder
- 左侧放系统分层示意，右侧 3 条能力说明
- 强调低延迟与可扩展
```

或更结构化（存 JSON/侧车字段也行）：

```json
{
  "title": "架构总览",
  "layout": "image_text",
  "image_role": "architecture",
  "slots": { "image": "...", "bullets": ["...", "..."] }
}
```

**大纲生成提示词**里写清：

- 允许的 layout 枚举：`list` | `image_text` | `metric` | `compare` | …  
- 科技类常见规则：出现「架构/流程/拓扑/对比/指标」时优先对应 layout  
- `image_text` 必须写清：图在左/右、图的内容角色（架构图/截图/示意）、文字侧要点数  

**内容生成**按 layout 走不同 schema，而不是统一「3～5 个标题-描述」：

| layout | 内容生成产出 |
|--------|----------------|
| `list` | item + desc（现有） |
| `image_text` | `caption` + `bullets[]` + `image_prompt`/`image_ref` |
| `metric` | 大数字 + 单位 + 一句解读 |
| `compare` | 左右两列要点 |

图从哪来（科技 PPT 关键）：

1. **占位**：模板里固定插画框，先出文，图用灰底+说明  
2. **图库检索**：按 `image_role` 从素材库选  
3. **生成图**：用 `image_prompt`（架构示意）——可控性差，适合内部稿  
4. **知识库附图**：RAG 命中带图文档时挂 `image_ref`  

对毕方更稳的是：**先 1+2，大纲强制带 layout；内容生成只填文字槽位和选图指令。**

### 和「选型 Agent」的关系

- **有指定结构**：大纲已写 `layout: image_text` → **不再选型**，只 Writer + Renderer  
- **未指定**：才用 Agent/规则补全 layout  
- 科技模板可默认：`架构*→image_text`，`指标|增速|%→metric`，其余 `list`  

### 小结

- 风格：不要按章混皮肤；换的是 **结构类型**，不是配色套装。  
- 图文：在 **大纲生成** 就输出 layout + 图角色；**内容生成** 按该 layout 的字段写；渲染用对应图文模板页。  

这样「指定图文结构」是产品能力，而不是生成后再猜。若要写进 `req/ppt生成设计.md`，可切 Agent 模式让我按这个结构落文档。
