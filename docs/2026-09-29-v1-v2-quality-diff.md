## 六、修复建议（可直接交 Cursor）

### 6.1 资产池按绑定源文档过滤（最高优先）

- 位置：材料池 `key_assets` 构建处 / `backend/app/services/kb_service.py:1443`（按 chunk 键带出 asset_ids）
- 做法：`key_assets` 只收 `source == 绑定源文档` 的资产；跨文档资产默认**丢弃**；仅在显式扩库检索（`retrieval_scope=kb_supplement`）时保留，且**强制在 caption 前置「来源：<文档名>」**
- 验收：以本任务为样本，段级插图清单的目标文档应 100% 等于绑定源文档

### 6.2 解析器必须容纳退化形态，且绝不允许透传

- 位置：`frontend/src/components/DocUtil/ViewItem4Doc.ts`（契约）→ figure 解析处
- 正则放宽：`` ```?\s*(figure|figureref)\s*:?\s*kb:(...) ``，caption 支持同行与换行两种
- **硬约束：任何形如 ```figure / ```figureref 的围栏，若无法解析，必须转【图片缺失】占位或阻断，禁止落入正文**

### 6.3 断言改为非空真

- 位置：handoff 记录的 `found.length === seq.length` 断言处
- 补 `seq.length > 0` 前置条件；或改为「模型输出中 figure 围栏计数 == 成功注入计数 + 占位计数」，任何缺口即抛错

### 6.4 新增「内部标记泄漏闸」（建议并入第四道闸）

- 输出前扫描 docx 全文，命中 ```` ```figure ````、`figureref`、`kb:`、`asset_id`、`caption:` 等模式即阻断
- 本轮若已有此闸，6 处泄漏会被一次拦下

### 6.5 ref 合法性校验

- 位置：ref 生成处
- 追加：ref 中的 `文档名` 必须命中知识库文件列表；`asset_id` 必须命中该文档的资产清单
- 本轮 4 处错 ref 中有 1 个文件名根本不存在（`…商务男士衬衫男装大盘.pdf`），说明 ref 是**拼接构造**而非原样复制，与 prompt 的"原样复制"要求不一致

### 6.6 表格闸回调

- `filterTableBlockByEvidence` 增加"证据充分性"判据（表内数值能在 chunk 中逐格命中即保留），而不是整表丢弃
- 价格带 / 属性占比这类天然表格化的数据应优先保表

## 七、层级与目录结构诊断（WorkBuddy 实测补充）

> 本节回答两个现场提问：「章节没有第三级？」「二级标题很繁复？」——**两者都成立，且同源**；另附一条模板级 P0（目录全错的真因）。

### 7.1 只有两级标题：确实没有第三级

| 实测项 | 值 |
|---|---|
| `heading 1`（styleId `1`）段落 | **4** 条（章） |
| `heading 2`（styleId `2`）段落 | **50** 条（段） |
| `heading 3`（styleId `3`）段落 | **0** 条 |
| 正文 `af4` | 50 条 |

契约（`frontend/src/components/ChatUtil/OutlinePromptComposer.ts:286-294`）只定义三级 Markdown：`#` 文题 / `##` 章 / `###` 段。映射到 docx 后 `###` 就是 **h2**，即「最细一级」——**所以正文天然只有两级，不存在第三级可落**。

**关键澄清**：模板备好了三级样式。`docTemplate-simple.docx` 的 `styles.xml` 里 styleId `1`–`9` = `heading 1`–`heading 9` 全部存在（`3` = `heading 3`，且带 `numPr numId=1 ilvl=2`）。**是契约没有三级，不是模板没有三级。**

### 7.2 二级标题繁复：量化为「数据句被当成了标题」

| 指标 | 实测 |
|---|---|
| h2 平均长度 | **42.0 字** |
| h2 中位长度 | **52 字** |
| h2 最长 | **79 字** |
| >50 字的 h2 | **27/50 条（54%）** |
| 主题型 h2（无数字、无引用） | **15 条**（平均 12.1 字，最长 19） |
| 数据型 h2（含数字或 `[文档N]`） | **35 条**（平均 54.8 字） |
| 带 `[文档N]` 的 h2 | **35/50 = 70%** |

交替模式极其规整——15 个主题型，每个后面紧跟 2~3 条数据型：

```
「男装大盘销量与销售额双增」        → 紧跟 2 条数据型 h2
「polo衫主力价格带的销量与销售额结构」→ 紧跟 3 条数据型 h2
「男士衬衫厚薄与袖型占比」          → 紧跟 2 条数据型 h2
```

**判定：模型其实在输出两层信息（主题 → 该主题下的 N 条数据证据），但只有一级标题可用，于是压平成了同一个 h2。** 这同时解释了 §五-4 的「标题-正文复述」：数据句标题本身就是正文首句被抽出来当标题。

### 7.3 这与「表格全灭」是同一件事的两面

V2 表格 14 → 1（§五-2），而同一份文档有 35 条数据句占据了 h2。价格带结构、属性占比、位次排行这些**天然表格数据**，既进不了第三级、又进不了表，只剩「挤进标题」一条路。
→ **修表格闸与修层级是同一个动作的两个方向**：给数据一个容器。

### 7.4 【模板级 P0】目录编号/页码全错的真因：模板目录区藏了第二套循环

`frontend/public/docTemplate-simple.docx` → `word/document.xml` 实测段落序：

| 段 | 样式 | 文本 | 域 |
|---|---|---|---|
| 37 | TOC1 | `{#chapters}1` | fldChar begin/separate + `TOC \o "1-3" \h \z \u` + `PAGEREF _Toc182955956` |
| 38 | TOC1 | `1{label}1` | `PAGEREF _Toc182955957` |
| 39 | — | `{#paragraphs}` | — |
| 40 | TOC2 | `1.1{label}1` | `PAGEREF _Toc182955958` |
| 41 | — | `{/paragraphs}` | — |
| 42 | TOC1 | `{/chapters}1` | `PAGEREF _Toc182955959` |
| 43 | 目录 1 | — | TOC 域 `fldChar end` |
| 46 | h1 | `{#chapters}` | 挂 10 个历史书签 |
| 47 | h1 | `{label}` | `_Toc182955957` |
| 49 | h2 | `{label}` | `_Toc182955958` |
| 53 | h1 | `{/chapters}` | `_Toc182955959` |

**目录区不是真目录，是一个「手搓目录」的循环体**：`{#chapters}`/`{#paragraphs}` 第二套循环直接写在 TOC 段落里，靠 docxtemplater 把标题填进条目。编号 `1` / `1.1` 与页码 `1` **都是模板里的字面常量**。

V2 成品与之一一吻合：

- 目录条目 **59 条**（TOC1 ×9 + TOC2 ×50），编号全为 `1`（9）与 `1.1`（50），页码全为 `1`；
- `bookmarkStart` 唯一名只有 **3 个**，而 `_Toc182955958` 出现 **50 次**（h2 的 `{label}` 段在循环体内被复制 → **书签重名**）；
- 59 条 `PAGEREF` 只指向 4 个目标，`_Toc182955958` 被引用 50 次 → **页码必然全部解析到同一处**；
- 用户看到的「5 条孤立页码 1」= `{#chapters}1` / `{/chapters}1` 这类标签段渲染后剩下的字面 `1`。

修法：

1. **目录区删掉手搓循环**，只保留一个真 TOC 域（`TOC \o "1-3" \h \z \u`），清空其缓存结果并给 `fldChar begin` 加 `w:dirty="true"` → Word 打开时自动重建（与题注 SEQ 域「更新域」的既有约定一致）。
2. **书签唯一化**：任何位于循环体内的 `_Toc*` 书签，渲染后必须重命名为唯一值。
3. **清理正文 h1 上挂的历史书签包**（段 46 挂着 `_Hlt…` + 9 个 `_Toc…` 遗留书签）。

### 7.5 建议修法（按性价比排序）

**A（P0，零模板改动，当天可验）段题瘦身**

- `DOC_OUTLINE_SKELETON`（`OutlinePromptComposer.ts:284-296`）给段题加硬约束：**≤14 字、禁阿拉伯数字、禁 `[文档N]`、禁逗号并列**；数据一律留给正文与表。
- 解析层加「标题体检」（`ViewItem4Doc.ts:598` 附近）：`###` 标题命中 `\d` / `[文档` / 长度 > 20 → 判为数据句，**降级为正文首句引导**（不占 h2）+ Warn（不拒单，与八·3 同风格）。
- 预期：h2 中位 52 字 → ≤14 字；数据句回归正文，§五-4 的标题复述同步消失。

**B（P0，结构正解，需动模板）加真三级**
